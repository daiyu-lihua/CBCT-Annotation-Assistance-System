# 本插件使用手册（3D Slicer CBCT Annotator）

> 适用人群：B 组成员、团队成员、后续标注操作员（普通用户）。
> 本文介绍如何加载本插件，并按"导入 → 框选 → 分割 → 修正 → 质检 → 导出"的
> 完整闭环用插件完成一份牙科 CBCT 的辅助标注。

---

## 0. 前提条件

- 已安装 3D Slicer（5.x，任意版本可用；下文 `<你的 ... 路径>` 均指 clone/解压本仓库到本机后的实际位置）。
- 一份要标注的 CBCT 影像（`nii / nii.gz / nrrd / dicom`），放在你本机任意位置，例如：
  `<你的数据路径>\1.nii`。
- （可选，需要 AI 分割时）已启动本地推理服务端，见
  [本地推理服务端说明](../../implementation/server/inference/README.md)。

---

## 1. 首次安装：把插件加入 Slicer 模块路径

只需做一次：

1. 打开 3D Slicer。
2. 菜单 `Edit（编辑）→ Application Settings（应用设置）`。
3. 左侧选 `Modules（模块）`。
4. 右侧 `Additional module paths` 点 `+`，选中本仓库的插件文件夹：
   ```
   <你的项目路径>\CBCT_Annotation_Assistance_System\user\plugin
   ```
   （`<你的项目路径>` = 你本机 clone 仓库的实际位置；选到 `user\plugin` 这一层）
5. 点 `OK` 保存，**重启 Slicer**。

重启后，顶部模块选择框输入 `CBCT`，点 **CBCT Annotator** 即打开插件面板。

---

## 2. 改代码后如何刷新（不用重启）

修改了 `CBCTAnnotator.py` 或 `ApiClient.py` 后，在 Slicer 底部 **Python Console**
输入并回车：

```
slicer.util.reloadScriptedModule('CBCTAnnotator')
```

看到返回 `<module 'CBCTAnnotator' from ...>` 即刷新成功，面板取最新代码。
若报红色异常，说明代码有 bug，把错误信息发开发人员。

> 如果刷新后界面没完全更新，可在 **Developer（开发者）→ Reload & Test，
> 选择本项目** 做一次更彻底的重新载入。

## 3. 面板各卡片说明（自上而下）

| 卡片 | 作用 |
|------|------|
| 数据导入 | 选择 CBCT 影像并加载显示，信息卡显示尺寸/间距 |
| ROI 选择 | 新建可拖动的框，框选要分割的牙弓区域，读取坐标 |
| 服务连接 | 填服务地址、测试连接（默认 `http://127.0.0.1:8000/api/v1`） |
| 模型与配置 | 从服务端拉取可用模型、推理模式、标签模板 |
| AI 分割 | 选择模型与模式，点击开始分割；完成后叠加显示结果 |
| 人工修正 | 打开 Segment Editor 修正边界，读取修正结果 |
| 标签质检 | 对修正后的标签做质量检查 |
| 结果导出 | 导出 nnunet 训练数据包 |
| 运行状态 | 状态栏 + 日志区（所有反馈都看这里） |

## 4. 完整标注流程（第 1 次跑通请按序）

> 提示：全程每一步都有反馈，看**面板底部运行状态 + 日志**即可知道是否成功。

### 第 1 步 连接服务
- "服务连接"卡，把地址填成 `http://127.0.0.1:8000/api/v1`
  （先启动 mock server，见 §0）。
- 点 **连接测试** → 状态变绿"已连接"，日志无报错。

### 第 2 步 加载配置
- "模型与配置"卡，点 **加载可用模型与模板**。
- 确认模型、推理模式、标签模板三个下拉框都出现内容。

### 第 3 步 导入影像
- "数据导入"卡，点 **选择影像** → 选中 `1.nii`。
- 点 **加载并显示** → 切片视图出现 CBCT，信息卡显示 640×640×400、间距 0.25。

### 第 4 步 框选 ROI
- "ROI 选择"卡，点 **新建 ROI 框** → 出现一个透明框。
- 在**3D 视图**（右下角）用鼠标拖动/缩放，把框住上下牙那排牙齿。
- 点 **读取 ROI 坐标** → 下方显示 `起点 (x,y,z) · 尺寸 (x,y,z) 体素`。

### 第 5 步 智能推荐 + 分割
- "AI 分割"卡，点 **智能推荐推理模式** → 模式下拉自动选中并显示理由
  （小块=fine 精细 / 适中=balanced / 大块=fast）。
- 正常使用当前项目模型时，选择 `toothseg-semantic-05mm`。
- 如果只是测试插件流程，可选择 `mock-simple-cube`。
- `toothseg-full` 是未来高级模式接口，占位保留，当前不会运行完整双分支。
- 点 **开始分割** → 进度条转动，完成后切片视图出现 `AI_Seg_Result` 叠加色块。

### 第 6 步 人工修正
- "人工修正"卡，点 **打开编辑器** → 进入 Slicer 的 Segment Editor，
  用画笔/橡皮对 AI 结果修正边界、补漏标。
- 修正完，点 **读取修正结果** → 把修正后的标签保存下来。

### 第 7 步 标签质检
- "标签质检"卡，点 **开始质检** → 显示"质检通过"或发现的问题数量。
- 有问题时看**日志区**列出的问题明细（空标签/编号重复/连通域/体积异常等）。

### 第 8 步 导出训练数据
- "结果导出"卡，点 **导出训练数据** → 生成 nnunet 数据包，
  提示文件数与导出目录。该数据可用于后续训练/反哺模型。

## 5. 常见问题（FAQ）

| 现象 | 原因 / 解决 |
|------|------------|
| 面板打不开 / 模块里找不到 CBCT | 模块路径没加对，或改代码后没刷新（§1、§2） |
| 连接测试红字"⚠" | mock server 没启动，或地址不对（§0、第 1 步） |
| 加载影像后信息卡间距显示 1.0 而非 0.25 | 旧版本 bug，刷新插件到最新（§2） |
| 新建 ROI 框后看不到框 | 到**3D 视图**（右下角）查看，框默认显示在三维视图 |
| 开始分割没反应 / 报"尚未读取 ROI" | 先做第 4 步读取 ROI 坐标 |
| 日志出现红字异常 | 复制错误信息发给开发人员 |
| 分割结果跑偏 / 错位 | ROI 坐标系不对，重新框选并读取坐标 |
| 打开 **View → Python Interactor + Error Log** 看不到报错？ | 插件一加载失败，红色堆栈会打印在这两个面板，直接发给开发人员 |
| 报 `No module named 'requests'` | Slicer 一般自带 requests；若确实缺，在 Python Console 执行 `slicer.util.pip_install('requests')` |
| 连接报错提示"无法连接服务端"、下拉框空 | 后端没启动或 `/config` 返回空，属正常（前端空是因为后端没数据），确认日志错误码即可 |

## 6. 提醒（重要）

- **不要**把真实患者 CBCT 原始数据或大体积模型权重推到公开 GitHub；
  Demo 数据须脱敏。
- `data/outputs/` 生成的结果文件已在 `.gitignore` 忽略，不会误入库。
- `toothseg-semantic-05mm` 输出的是已映射到本项目规范的语义标签图，当前默认按 0.5mm 降采样运行，是本阶段主流程。
- `mock-simple-cube` 输出的是假 mask（ROI 内实心色块），仅验证链路，不代表真实分割效果。
- `toothseg-full` 当前仅作为未来高级模式接口占位。
