## 一、系统边界（前端只管这三件事）

```
┌────────────── 3D Slicer 前端插件（本文件范围） ──────────────┐
│  1. 可视化与交互：CBCT 导入、ROI 选择、结果展示、人工修正      │
│  2. HTTP 调用：把请求发给本地推理服务端（/api/v1/*）           │
│  3. 提示与导出：显示 Agent 提示、质检报告、导出训练数据        │
└──────────────┬───────────────────────────────┬───────────────┘
               │   只通过 HTTP 接口，不碰模型、不碰训练
               ▼
      ┌─────────────────┐        ┌─────────────────┐
      │ 本地推理服务端    │  ←→   │ Agent 模块(状态/质检)│
      │ (/predict 等)   │        │ (/recommend_mode等)│
      └─────────────────┘        └─────────────────┘
```

**铁律**：前端插件**不加载模型、不跑训练**，所有 AI 计算都走 HTTP 接口。前端只负责"把图像路径/ROI 交出去，把 mask/报告拿回来显示"。

## 二、接口对接方案（前端插件视角）

### 2.1 通用约定

| 项 | 约定 |
|----|------|
| Base URL | `http://127.0.0.1:8000/api/v1`（可配置，支持院内局域网 IP） |
| Content-Type | `application/json` |
| 坐标顺序 | `[x, y, z]` |
| 图像/标签返回 | 优先 `nii.gz`，兼容 `seg.nrrd` |
| 质检报告 | `quality_report.json` + `quality_report.md`（返回路径，前端读取） |
| 错误统一格式 | `{status:"error", error_code, message, details}` |
| 前端请求方式 | 3D Slicer 用 Python `requests` / `urllib`，**必须异步**（开子线程），避免界面卡死 |

统一错误码（前端要做的映射)：`IMAGE_NOT_FOUND`、`UNSUPPORTED_FORMAT`、`INVALID_ROI`、`MODEL_NOT_LOADED`、`CUDA_OUT_OF_MEMORY`、`PREDICTION_FAILED`、`LABEL_NOT_FOUND`、`LABEL_FORMAT_ERROR`、`EXPORT_FAILED`。

### 2.2 前端需要对接的接口清单

| 接口 | 方法 | 用途（前端侧） |
|------|------|----------------|
| `/status` | GET | 连接后检查服务/模型/硬件是否就绪，决定能否启动推理 |
| `/config` | GET | 拉取"可用模型 + 推理模式(fast/balanced/fine) + 标签模板列表"，填充下拉框 |
| `/cases` | POST | 创建本次标注任务，拿到 `case_id` 和状态文件路径 |
| `/images/inspect` | POST | 读取 CBCT 基础信息（shape/spacing），前端显示数据规模 |
| `/agent/recommend_mode` | POST | Agent 根据 ROI+硬件推荐 fast/balanced/fine，前端拉取并默认选中 |
| `/predict` | POST | 核心：发图像路径+ROI+模型+模式，拿回 AI 初分割 mask 路径 |
| `/check_label` | POST | 对人工修正后的标签跑质检，拿到报告路径+问题列表 |
| `/export` | POST | 导出训练数据包（image/label/报告/metadata）到本机目录 |
| `/agent/log` | POST | 记录本次标注事件，供 Agent 经验沉淀 |

### 2.3 各接口对接细节（前端要处理什么）

#### A. GET `/status`（服务与模型就绪检查）
- **前端动作**：启动时、每次点击"开始分割"前调用。
- **成功判断**：`service=="running"` 且 `model.loaded==true`。否则弹提示："模型未加载，请检查服务端 /status"。
- **前端显示**：下方状态栏显示 设备类型/显存空闲、模型名、服务地址连通状态。

#### B. GET `/config`（初始化下拉框）
- **前端动作**：启动时拉一次，填充三个下拉框：
  - 模型列表（`models[].model_id`）
  - 推理模式（`inference_modes` 的 key：fast/balanced/fine），可带中文说明
  - 标签模板（`label_templates[].template_id`）
- **注意**：服务端有多个模型/模板时，本次病例的默认值取第一个，用户可改。

#### C. POST `/cases`（创建病例）
- **请求体前端负责填**：`image_path`（用户选的 CBCT 路径）、`image_format`（后缀推断 dicom/nii.gz/nrrd）、`label_template_id`（当前下拉选择）、`operator`（当前用户名）。
- **前端拿到**：`case_id`、`case_state_path`。前端把 `case_id` 存到插件内存，后续所有接口都带它。

#### D. POST `/images/inspect`（图像信息检查）
- **请求体**：`case_id` + `image_path`。
- **前端动作**：显示 `shape: [512,512,320]`、`spacing`、估算大小到界面；用于在选 ROI 前让用户感知数据量级。

#### E. POST `/agent/recommend_mode`（推理模式推荐）
- **请求体**：`case_id` + 当前 `roi{start,size}` + 目标结构（如 `["tooth","pulp","implant"]`）。
- **前端动作**：把返回的 `recommended_mode` 作为推理模式下拉框的**默认选中**，并展示 `reason` 说明文字；`fallback_mode` 在推荐失败时兜底。
- **提示**：如果 ROI 还没选，本接口可跳过，用户手动选模式。

#### F. POST `/predict`（核心，AI 初分割）
- **请求体**：`case_id`、`image_path`、`roi{start,size}`、`model_id`、`mode`、`targets`、`output_format:"nii.gz"`、`output_dir`。
- **前端动作**：
  1. 校验：已建病例、已选 ROI、已选模型和模式，缺一不可，缺则提示。
  2. 用**进度对话框**等待（推理可能十几秒到几十分钟），禁用界面防重复点击。
  3. 拿到 `prediction_id`、`mask_path`、`confidence_path`，进结果加载。
- **前端可做**：记录 `runtime.elapsed_ms`、`device` 显示在状态栏。

#### G. POST `/check_label`（标签质检）
- **请求体**：`case_id`、`label_path`（人工修正后的标签）、`label_template_id`、`checks`（默认全开列表）。
- **前端动作**：展示返回的 `summary`（error/warning/passed 计数）和 `issues[]` 列表；把 `quality_report.md` 路径存到"查看报告"按钮。前端可对每条 issue 做不同底色（error=红 / warning=黄）。

#### H. POST `/export`（导出训练数据）
- **请求体**：`case_id`、`image_path`、`label_path`、`export_format`、`include_report`、`output_dir`。
- **前端动作**：导出前建议自动先跑一次 `/check_label`；成功后提示并给出 `export_dir`，在 Slicer 里弹出目录；导出文件清单显示在结果面板。

#### I. POST `/agent/log`（经验记录）
- **请求体**：`case_id`、`event`（如 `label_corrected`、`case_exported`）、`operator`、`payload`。
- **前端动作**：在"修正完成""导出完成"等节点静默 POST，失败不阻断主流程（放 try/except，仅 console 记 warning）。

## 四、关键技术点提醒

1. **坐标换算（最易错）**：Slicer 内部用 RAS，服务端接口用 IJK `[x,y,z]`。ROI 的 `start` 必须是 IJK 体素坐标，前端读 ROI 节点时要 `GetIJKOriginAndSpacing` 换算，前后端不一致会导致 mask 错位。验收时务必对比同一体素原点。
2. **UI 不卡顿**：`/predict` 等长接口必须放子线程 + 进度框，否则 Slicer 界面假死。
3. **mask 显示格式**：AI 返回 `nii.gz`，优先转 Slicer `Segmentation`（可编辑），训练导出再转 `LabelMap`。
4. **假 mask 调试**：在服务端未就绪前，前端可用本地生成的简单 LabelMap 充当 `mask_path` 验证"导入→显示→修正→导出"流程，不依赖模型（B 组不必等 A 组）。
5. **服务地址可配置**：默认 `127.0.0.1:8000`，界面留输入框，支持连院内局域网其他机器运行服务端。
